# Phase 8 本地用户测试协议

这是受控 loopback 测试，不是生产上线或公开网络测试。测试前启动 `docs/service.md` 中的服务和 `frontend/README.md` 中的静态前端。

## 固定步骤

对每条任务重复：

1. 上传同一个已验证的 `imax.mp4`（或项目外置目录中另一条已授权测试视频）。
2. 输入任务表中的查询，等待任务进入终态。
3. 点击一个候选片段，确认本地视频预览可定位；必要时填写调整开始/结束秒数。
4. 点击一个反馈按钮。
5. 记录任务是否完成、首个候选是否可用、边界是否调整、完成耗时和失败原因。

若任务先进入 `TIMEOUT`，继续等待结果端点；出现带 `degraded=true` 的 Level-2
候选后，仍可选择候选并提交反馈。若结果尚未写入，客户端按 `409` 重试，不能把
空结果记录为成功。

## 查询任务

至少完成 20 次有效操作；同一查询可重复，但必须为独立 task。若实际样本不足，按实际数量报告，不能补写。

| 编号 | 查询 | 主要观察 |
|---:|---|---|
| 1 | 找到视频开头的主要场景 | 首结果是否可预览 |
| 2 | 找到人物出现在画面中的片段 | 首结果是否相关 |
| 3 | 找到画面中主体最清晰的片段 | 是否需要调整开始 |
| 4 | 找到人物在场景中移动的片段 | 是否需要调整结束 |
| 5 | 找到画面变化最明显的片段 | 结果是否重复 |
| 6 | 找到包含主要物体的片段 | Top-3 是否有可用结果 |
| 7 | 找到视频中部的场景 | 任务完成时间 |
| 8 | 找到视频结尾附近的场景 | 长视频等待感受 |
| 9 | 输入一个视频中不存在的目标 | 是否能诚实反馈无目标 |
| 10 | 重复第 3 条查询 | request/task 独立性 |

## 结果记录

反馈服务会把 `task_id`、`video_id`、原始 `query`、候选、反馈标签、可选边界调整和 model/policy version 写入受控外置运行时 JSONL；不写入原始视频内容或视频路径。测试完成后，统计：

- 有效操作数、失败数；
- `accepted` 比例和各反馈标签计数；
- 首结果采用率（若测试者按固定规则记录）；
- 边界调整秒数（仅对填写了调整的样本）；
- 任务完成时间和取消/超载次数。

在真实参与者完成前，G8 保持 pending；自动化 stub 协议记录不能替代本协议。
